# CONTENT_GUIDE.md

이 문서는 공지사항과 활동보고 Markdown 작성 규칙입니다.

## 콘텐츠 원칙

- 공식 기록 중심으로 작성한다.
- 과도한 홍보성 표현을 피한다.
- 사실, 일정, 진행 내용, 결정 사항을 명확히 쓴다.
- 원문의 날짜, 인명, 금액, 사건 결과를 임의로 바꾸지 않는다.
- 공개 전 민감 정보와 실명 공개 필요성을 확인한다.

## 파일 위치

공지사항:

```text
content/notices/YYYY-MM-DD-title.md
```

활동보고:

```text
content/activities/YYYY-MM-DD-title.md
```

## Frontmatter

기본 형식:

```yaml
---
title: "게시글 제목"
date: 2026-07-08
category: "공지사항"
summary: "목록에 표시될 요약"
author: "Altibase 노동조합"
thumbnail: ""
pinned: false
tags:
  - "태그"
draft: true
slug: "post-slug"
---
```

필드 설명:

- `title`: 게시글 제목
- `date`: `YYYY-MM-DD`
- `category`: `공지사항` 또는 `활동보고`
- `summary`: 목록과 SEO 설명에 쓸 짧은 요약
- `author`: 작성 주체
- `thumbnail`: 대표 이미지 경로. 없으면 빈 문자열
- `pinned`: 목록 상단 고정 여부
- `tags`: 태그 배열
- `draft`: 공개 여부. 초안은 `true`
- `slug`: 상세 페이지 URL에 쓰는 고유값

## 공개 규칙

- 새 글은 기본적으로 `draft: true`로 만든다.
- 내용 검토, 민감 정보 확인, 링크 확인 후 `draft: false`로 변경한다.
- `draft: true` 글은 목록과 상세 페이지에 노출하지 않는다.

## 공지사항 작성 규칙

추천 구조:

```markdown
## 안내 내용

공지 내용을 간단히 설명합니다.

## 대상

- 대상 1
- 대상 2

## 일정

- 일시:
- 장소:
- 문의:
```

원칙:

- 제목은 조합원이 바로 이해할 수 있게 쓴다.
- 날짜, 대상, 행동 요청이 있으면 명확히 분리한다.
- 불필요한 수식어를 줄인다.

## 활동보고 작성 규칙

추천 구조:

```markdown
## 요약

이번 활동보고의 핵심 내용을 2~4문장으로 정리합니다.

## 주요 활동

### 활동명

- 일시:
- 장소:
- 주요 내용:

## 진행 중인 현안

### 현안명

- 진행 상황:
- 다음 조치:

## 다음 일정

- 일정 1
- 일정 2
```

원칙:

- “무엇을 했는가”, “언제 진행했는가”, “주요 내용은 무엇인가”를 중심으로 작성한다.
- 월간 활동보고는 같은 구조를 유지한다.
- 장황한 설명보다 목록과 H3 섹션을 활용한다.

## 용어 표기

통일 표기:

- `부당노동행위`
- `근로시간면제자`
- `노사협의회`
- `활동보고`
- `조합원`

자동 변환 대상:

- `부당 노동 행위` → `부당노동행위`
- `근로 시간 면제자` → `근로시간면제자`
- `노사 협의회` → `노사협의회`

## 이미지 규칙

이미지는 가능하면 다음 위치에 둔다.

```text
public/images/activities/{slug}/
```

Markdown에서는 활동보고 상세 페이지 기준으로 경로를 적는다.

```markdown
![이미지 설명](../../images/activities/{slug}/image-name.png)
```

원칙:

- 이미지 설명 alt text를 작성한다.
- 표나 이미지 안의 텍스트가 너무 작으면 본문에 요약을 함께 적는다.
- 불필요한 개인정보가 보이는 이미지는 사용하지 않는다.

## 링크 규칙

- 외부 링크는 원문 또는 참고 자료가 명확할 때만 사용한다.
- Notion 원문 URL이나 네이버 카페 원문 URL은 `sourceUrl`에 남길 수 있다.
- 원문 URL은 선택값이지만, 공개 가능한 원문이 있으면 기록하는 것을 권장한다.

## Union Publisher Lite 사용

실행:

```bash
npm run content:app
```

접속:

```text
http://localhost:4177
```

사용 순서:

1. Markdown 또는 Notion ZIP 선택
2. 원문 URL 입력. 선택 사항
3. `분석 및 변환`
4. 원문/변환본 비교
5. 검증 결과 확인
6. 필요한 문장 수정
7. `활동보고 생성`
8. `npm run check`
9. `npm run build`
10. Git 브랜치와 PR 준비

주의:

- URL에 `?file=...`을 직접 넣지 않는다.
- 브라우저 캐시 문제 시 `Ctrl + F5`로 강력 새로고침한다.
- Notion ZIP 안에 ZIP이 다시 들어 있는 경우도 지원한다.
